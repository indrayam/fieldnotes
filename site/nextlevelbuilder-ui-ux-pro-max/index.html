Use it for

One answer to a narrow question: a palette for a fintech app, a chart type, an a11y rule, a GSAP preset.

Not for

Building or restyling a page. Use Impeccable or Hallmark for that.

Its own rule

Build each query around one dominant intent, using 2–5 meaningful terms and one useful constraint such as product, platform, or interaction.

Its own skip list

Skip it for pure backend logic, API/database design, non-visual performance work, infrastructure/DevOps, or non-visual scripts.

Its own RTL rule

caveats means the style or product encodes reading direction — say so before recommending it, and propose a mirrorable alternative when the user needs a strict RTL build.

Where --rtl is refused

Only with --domain style or product. With --domain ux, --stack or --design-system the CLI exits with a usage error, e.g. --rtl is not supported with --design-system; run a separate --domain style or --domain product query.

Commands

Install Once, Then Call search.py

npm install -g ui-ux-pro-max-cli && uipro init --ai cursor     # or claude, codex ...
# Claude Code plugin instead:
/plugin install ui-ux-pro-max@ui-ux-pro-max-skill

S=~/.claude/skills/ui-ux-pro-max/scripts/search.py              # path differs per harness
python3 $S "error summary validation" --domain ux
python3 $S "fintech dashboard" --domain color -n 3
python3 $S "badge chip overflow nowrap" --stack html-tailwind
python3 $S "internal analytics" --design-system -p Acme          # prints; add --persist to write
python3 $S "apple native" --domain style -n 1                   # new in 2.15.0
python3 $S "admin dashboard data" --domain style --rtl=full     # RTL filter, style/product only
python3 $S "chart donut" --stack nuxt-ui                        # Nuxt UI 4.12 rows

persist is cautious

If design-system/<project-slug>/MASTER.md already exists, --persist skips writing and leaves it untouched unless you also pass --force.

Python only

No dependencies. Try python3 if python is missing.

Fleet Rule

Pick One Builder Per Project

This rule sits on all three Design Skills sheets.

The rule

Never load Impeccable, Hallmark and Taste Skill together on one project. Pick one builder.

Why

Each ships its own floor, bans and stamp. Impeccable writes PRODUCT.md, DESIGN.md and .impeccable/. Hallmark writes .hallmark/ and a CSS stamp. Two builders on one page argue: one deals a theme, the other rolls a visual world, and the agent splits the difference.

Rule of thumb

App, dashboard, settings, existing product UI: Impeccable. New landing or marketing page: Hallmark. Need a palette, font pair or UX rule: UI/UX Pro Max. It is a lookup, so it can sit next to either builder.

You are here

UI/UX Pro Max is not a builder, so it can sit next to any one of them as a lookup. The rule is about builders: Impeccable, Hallmark or Taste Skill, one per project.
