Who it is for

A new landing, launch or product page where the first screen has to sell.

What you get

One self-contained HTML/CSS page, stamped with its decisions, linted at eight widths and reviewed by a fresh-context subagent.

Why It Exists

Models Fall Into The Same Ten Tells

1

Hallmark holds a hard floor and then gets out of the way.

2

the eyebrow above every heading, tracked-capital labels, one coloured word in a headline, a page of empty frames or nothing but photographs, a hero that misses its screen, an email sign-up at the end of every page, a form that says thanks without sending anything.

3

A fresh-context reviewer gets the last word.

Install

One Command, Global By Default

npx skills add nutlope/hallmark -g                       # every harness, every project
npx skills add nutlope/hallmark -g --agent claude-code   # one harness (codex, cursor, opencode, github-copilot)
npm i -g puppeteer-core                                  # + Chrome: needed for sloplint --render and screenshots
HarnessLands inInvoke

Codex CLI~/.agents/skills/hallmark$hallmark <prompt>
Cursor, OpenCodefinds the copies above/hallmark <prompt>

Why -g

-g installs for every project; leave it off to install into the current one.

Node

Needs Node 18 or later. Without puppeteer the static checks still run.

If it stays quiet

Name it: use hallmark to build .... Its description stops it from touching existing designs unless named.

The Verbs

Build Is The Default; Redesign And Audit Need Its Name

/hallmark a landing page for a dotfiles CLI       # build (deals 3 themes)
/hallmark Terminal: a landing page for burrow     # build in a named theme
/hallmark custom: ...                             # no theme, Floor still holds
/hallmark redesign ./src/app                      # keeps content + wiring, new system + layout
/hallmark audit ./index.html                      # report only, no edits

Rule

Never use it on an existing design unless the user names Hallmark, as in /hallmark redesign <path>.

Redesign safety

sloplint --before records every link, field, handler and heading first, sloplint --kept fails the redesign if one went missing.

Lighter redesigns

Say keep the layout for a restyle or polish for only the tells.

What about "study"?

No study verb ships in v2. SKILL.md lists only redesign <target> (a full redesign keeping content and wiring) and audit <target> (a report). "study" only shows up as an eval brief (eval/, b6) that expects the skill to decline.

How A Build Runs

Ask Once, Deal A Theme, Build The Hero Alone

The eight steps from SKILL.md, short.

  1. 0 Pre-flight. Reads fonts, palette, framework and any DESIGN.md, which overrides everything.

  2. 1 Ask once. Material, audience, use, tone. Or say go ahead. Facts are never inferred.

  3. 2 Shape. Names the visitor's job, then theme.mjs draw deals the page anatomy.

  4. 3 Direction. theme.mjs deal offers three themes; the agent picks one and says why.

  5. 4 to 5 Load and Picks. Loads one theme file, then posts a Picks block: your one chance to redirect.

  6. 6 Build. Hero first, linted with --stage hero and reviewed cold, then the rest.

  7. 7 Sweep. sloplint --render until clean, gates walked, fresh reviewer, then the material ask.

Sloplint

The Floor Is Enforced By A Script, Not A Prompt

node ~/.claude/skills/hallmark/scripts/sloplint.mjs page.html            # static checks
node .../sloplint.mjs page.html --render                                   # + eight widths in Chrome
node .../sloplint.mjs src/ --url http://localhost:3000/ --scope page --json
node .../sloplint.mjs ./src/app --before    # snapshot links, fields, handlers before a redesign
node .../sloplint.mjs ./src/app --kept      # fail if any went missing
# exit 1 on any FAIL

Findings And Gotchas

Named Colours Slip Past The Floor

From reading 7ec8682 and running sloplint on the box.

Bug Named colours are not caught

linear-gradient(purple,blue) passed both 2a (purple-to-blue gradient) and 48 (colour literal). The same gradient written as hex (#7c3aed,#2563eb) failed both. Floor rule 11 says never a purple-to-blue gradient, so the linter misses named colours.

Gap "study" is not a v2 verb

The brief listed build / redesign / audit / study. Only redesign and audit ship as verbs; build is the default.

Gap Version labels disagree

package.json and SKILL.md say 2.0.0; the commit that brought in v2 is titled "Hallmark v2.2".

Gap Theme count

README says forty-eight; references/themes/ has 48 theme .md files plus README.md (49 .md files).

Cost Strict copy rules

About 80 words per screen and no eyebrows or tracked caps. Great for landings, wrong for docs or dashboards. Use Impeccable there.

Copy before/kept for redesigns

Snapshotting every link and handler before a rewrite and failing if any disappear is worth stealing for any refactor.

Fleet Rule

Pick One Builder Per Project

This rule sits on all three Design Skills sheets.

The rule

Never load Impeccable, Hallmark and Taste Skill together on one project. Pick one builder.

Why

Each ships its own floor, bans and stamp. Impeccable writes PRODUCT.md, DESIGN.md and .impeccable/. Hallmark writes .hallmark/ and a CSS stamp. Two builders on one page argue: one deals a theme, the other rolls a visual world, and the agent splits the difference.

Rule of thumb

App, dashboard, settings, existing product UI: Impeccable. New landing or marketing page: Hallmark. Need a palette, font pair or UX rule: UI/UX Pro Max. It is a lookup, so it can sit next to either builder.

You are here

Hallmark is the builder for landing and marketing pages. Choose it, and leave Impeccable and Taste Skill unloaded on that project.
