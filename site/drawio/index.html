Skill explainer · jgraph/drawio-mcp

Draw.io

Every diagram becomes a native .drawio file first, then whatever format you asked for.

The official draw.io skill, shipped byte-identical to Claude Code, Codex, Copilot, Cursor and Antigravity. Author as Mermaid or XML, repair it, lay it out with ELK, and export with the XML embedded so every PNG stays editable. I read the skill, ran both servers’ test suites and the shared modules. Every diagram becomes a native .drawio file first, then is delivered in the requested output format, whether you authored Mermaid or XML.

Who it is for

Agents in terminals (Claude Code, Codex, Copilot CLI) where diagrams cannot render inline.

What you get

A .drawio, an embedded-XML PNG/SVG/PDF, or an app.diagrams.net link.

How It Works

Author, Repair, Lay Out, Deliver

The skill is one pipeline with two ways in.

1

Inline first. Inline viewer first. In chats that render diagrams, the MCP create_diagram tool wins.

2

Author. Mermaid when the desktop CLI exists; XML otherwise. If Mermaid was requested but no desktop CLI is available, author the same diagram as XML.

3

Repair. It changes nothing in a well-formed file, and needs only Node.js.

4

Lay out. The CLI's --layout step auto-positions XML-authored diagrams with the same ELK layouts as the editor's Arrange ▸ Layout menu and the draw.io MCP app server.

5

Deliver. Exports use double extensions so the name says the XML is inside.

Build Your Own

What To Steal

  1. One native artifact, many deliveries. Write the source format first; derive the rest.

  2. Prefer a layout engine to model coordinates. Ask for structure, not positions.

  3. Measure the model’s mistakes, then fix them in code. repair-xml.js says its three fixes covered all 15 broken diagrams out of 473.

  4. Detect the environment exhaustively. The Windows chain checks PATH, install paths, registry and other drives before giving up.

  5. Keep ports identical by CI.
