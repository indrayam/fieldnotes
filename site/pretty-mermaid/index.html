Pretty Mermaid

Mermaid to themed SVG, PNG or terminal text, with no browser in the loop.

A small Node skill over the beautiful-mermaid renderer: six diagram types, fifteen themes, three output formats and a batch runner. I read the skill, ran its smoke test and doc validator, and rendered every example in every format. Runs locally without a browser or DOM, with 15 built-in themes and custom colors.

Anyone putting diagrams in READMEs, PRs, chats or terminals.

How It Works

Write The Source, Render, Then Look At It

A seven-step loop, from SKILL.md.

1

Source first. Save new source as a .mmd file, preserving user terminology and relationships.

2

Render. Render with a named theme or explicit colors.

3

Inspect. Inspect the result. Fix syntax, clipping, crowded layout, or unclear labels and render again.

4

Don’t clobber. Do not overwrite an existing source or output file unless the user asked for replacement.

5

Be honest about limits. Report any renderer limitation instead of silently dropping unsupported syntax.

Bug The first-run auto-install never runs

render.mjs statically imports png.mjs, which imports @resvg/resvg-js. Without node_modules, Node fails at load time, before loadBeautifulMermaid() can run npm install. SKILL.md says “the CLI also attempts a first-run install”.

Gap No overwrite guard in the CLI

SKILL.md forbids overwriting; render.mjs overwrites silently. The rule depends on the agent.

Gap Bad syntax can render

A --> with no target produced an SVG and exit 0, so “confirm the command exits successfully” is not enough.

Gap THEMES.md is Chinese, and its table is off

The routed theme reference is in Chinese, and its quick table lists the accent as the foreground for several themes (e.g. tokyo-night-light #34548a vs fg #343b58 in code).

Copy No browser

resvg rasterizes the SVG, so PNG works in CI and sandboxes.

Copy A validator for the docs

validate-docs checks the Markdown, the SKILL.md length and that every theme has a preview.

Build Your Own

What To Steal

  1. Route by need, then by output. Two small tables pick the type and the format.

  2. Make the agent look at the render. Inspection is a step, not an afterthought.

  3. Ship starters. One working example per type.

  4. Keep the loader lazy. If you promise auto-install, import heavy dependencies after the check.
